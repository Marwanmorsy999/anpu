## How to read this

- **✓ HIT** — at least one finding matched the planted signal.
- **✗ MISS** — the signal was in scope and nothing matched. This is the
  cell that matters: a MISS is a documented detection gap, not a footnote.
- **○ expected miss** — the signal is out of scope for that profile by
  design (`safe` is passive; active engines run on `advanced`/`ultra`).
  Absence here is correct behavior, recorded so nobody mistakes it for a gap.
- **Unmatched** — findings matching no planted signal. Counted, never
  auto-labeled false positives: the harness cannot prove a negative.
  Finding counts are indicative context from the recorded run, not gated
  values — discovery timing makes them wobble a few points run to run.

We report detection rate (recall) per signal, not precision: precision
requires proven false positives, and automatically labeling unmatched
findings as false would be exactly the kind of scanner dishonesty this
project exists to oppose.

## Methodology

- Fixture: `tests/bench/server.py` (stdlib-only, loopback, fake secrets),
  started via `tests/bench/docker-compose.yml`. Homepage links every
  vector; short 404s; no security headers anywhere.
- Command: `anpu bench --target http://127.0.0.1:8901 --profiles
  safe,advanced` (run 1 of 1), default non-verbose scans. Verbose scans
  add ~25 `<tool> external run` info findings and are never benchmarked.
- Matching: case-insensitive title substring + category + URL path, per
  `ground-truth.yml`. Signal-level, not engine-level: a signal counts as
  HIT whichever engine caught it (see engine notes).
- Environment: no Nuclei binary installed, so the Nuclei stage contributed
  only its embedded fallback. Timings are excluded from the gated table
  (safe ≈ 3s, advanced ≈ 5min on the calibration machine).
- Refresh: `anpu bench --format markdown --refresh-docs docs/benchmark.md`;
  CI enforces with `--check`.

## Engine notes (what caught what)

Signal-level HITs hide engine-level gaps worth stating plainly:

- **open-redirect** was caught by redirectpack (`Open redirect confirmed`),
  never by the active engine's `open-redirect` rule. Suspected mechanism:
  the HTTP client follows the 302 to the unresolvable canary domain, so
  the rule's `3xx + Location` check never sees it (verified code path,
  `internal/active/open_redirect.go` vs `internal/http/client.go`).
- **reflected-xss** was caught by the dalfox embedded candidate, never by
  the active `xss-reflected` rule. Mechanism unproven — recorded, not
  diagnosed.
- **backup-zip** hit 3 of 4 calibration runs; the single miss was the
  first (cold) run, mechanism unproven. Tracked as non-gating (`gate:
  false` in ground truth) until root-caused.
- `/backup.zip`, `/go`, and `/search` were additionally flagged by the
  authz-tester as unauthenticated sensitive endpoints — corroboration,
  not double-counting.
- Calibration also observed safe-profile totals wobbling 8–12 findings
  across runs (timing-sensitive discovery); verdicts were stable.

## What ANPU did not detect

In the recorded run, every planted signal was detected at least once —
there are no signal-level misses to report, which is precisely why the
engine-level gaps above are listed instead. The benchmark's value is not
"5/5" but the standing offer: **any future MISS cell stays published
here until it is fixed or explained.**

Out of scope by design (never probed, never claimed): stored XSS
requiring JS execution, authenticated-only flows, and anything needing
`--adversarial` confirmation.

## Reproduce

```sh
docker compose -f tests/bench/docker-compose.yml up -d
go run ./cmd/anpu bench --target http://127.0.0.1:8901
go run ./cmd/anpu bench --target http://127.0.0.1:8901 --format markdown --check docs/benchmark.md
```

## CI

`.github/workflows/bench.yml` starts the compose fixture, builds ANPU,
and runs the `--check` gate: on weekly schedule, on demand
(`workflow_dispatch`), and on PRs touching scanners, reporting, the
harness, or the fixture. A verdict change fails the gate; refresh with
`--refresh-docs` after reviewing the diff.
